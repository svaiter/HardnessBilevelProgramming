# Put the visual paper on your website

## Upload now

Copy **the contents of `website/`** into a folder on your web host, for example
`bilevel-hardness/`. The entry point is `index.html`:

```text
https://your-domain.example/bilevel-hardness/
```

Alternatively, extract `bilevel-hardness-website.zip`; it contains that folder
already. You can rename or move it freely. All application assets, fonts, and Lean
source pages use relative URLs. No server-side code, installation, build service,
CDN, or ChatGPT account is needed to serve it. No rewrite rules are needed:
navigation uses URL fragments, such as `#/thm215/summary`.

Mathematics is stored as compact TeX in `data.js` and rendered in the browser.
KaTeX, its fonts and the paper's macros are bundled locally; no external service
is needed. The build still validates every formula before exporting. Keep
`math.js` and `vendor/katex.min.js` with the other assets when uploading.

For a static-site generator, copy `website/` into its directory for files served
without processing, for example Astro's `public/bilevel-hardness/`. On an ordinary
web host, upload it as a regular directory. Serve `.html`, `.js`, `.css` and font
files with their usual content types.

The exported site preserves the current author-preview labels. This operation
only prepares files; it does not upload anything or change the hosted private Site.

## Update after editing Lean

Keep the entire `visual-paper/` project in the Lean repository. From that folder:

```sh
npm run update
```

This refreshes the Lean snapshot from the current working tree, including
uncommitted and newly added, non-ignored Lean files; resolves the configured
declarations; rebuilds the site; and replaces `website/` and the ZIP. Upload the
new `website/` contents in place of the old ones, removing obsolete files.

To use a committed version instead:

```sh
npm run update -- --ref HEAD
```

To read another local clone:

```sh
npm run update -- --repo /path/to/HardnessBilevelProgramming --ref HEAD
```

Nothing is fetched, committed, pushed, deployed, or compiled with Lean by these
commands. They require Node.js, Pandoc, Python 3 and Git. JavaScript dependencies
are included in `vendor/`; no `npm install` is needed.

## What updates automatically

| Change | Result |
|---|---|
| Added comments or shifted lines | Source pages and line links update; baseline badges are retained. |
| Declaration moved to another file | Its qualified name is located if unique. |
| Lean code or dependencies changed | Sources update; Lean badges conservatively say review is needed. |
| Declaration renamed or removed | The link is marked unresolved, with details in `reports/lean-update.json`. |
| New theorem | Its declaration appears in `reports/lean-index.json`; add a paper node and mapping if it should appear on the map. |

`content/lean-map.json` is the small editable table connecting paper node IDs to
qualified Lean declaration names. For a rename, edit the `declaration` field and
optional file hint, then rerun `npm run update`. For example:

```json
"thm215": {
  "declaration": "Bilevel.Unconditional.thm215_eq",
  "file": "HardnessBilevelUnconditional/Main.lean",
  "status": "formalized"
}
```

The indexer finds source locations; it is not the Lean elaborator. Unusual syntax
or ambiguity is reported rather than guessed. Changed-code badges are deliberately
conservative because edits to an imported definition can affect an unchanged
theorem statement. Run the repository's `scripts/check.sh` separately when checking
the formalization.

The original audited paper text, corrections, citations and verdicts remain pinned
in `content/paper.json`, `source/repository/`, `SOURCE.lock` and `audit/`.
Updating Lean does not rewrite those mathematical claims. If a result changes,
update and review the corresponding paper node as a separate content edit.
`content/lean-baseline.json` records the reviewed source hashes; refreshing sources
does not silently move that review baseline.

## Keep versus upload

| Location | Purpose |
|---|---|
| `website/` | Upload this directory only. |
| `bilevel-hardness-website.zip` | Portable copy of the same upload directory. |
| `site/` | Edit layout, navigation and styling here. |
| `content/lean-map.json` | Edit result-to-declaration associations here. |
| `source/lean/` + `LEAN.lock.json` | Reproducible current Lean snapshot, generated by the update command. |
| `reports/lean-update.json` | Changed files and unresolved declarations from the last refresh. |

For layout-only edits, `npm run export` rebuilds the upload directory using the
existing Lean snapshot. Edit source files in `site/`, not the generated files in
`website/` or `dist/`, which are replaced on the next build.

### Integrate into samuelvaiter.com

Run `npm run export -- --svssg` to generate `website-svssg/` and
`bilevel-hardness-svssg.zip`. Copy the **contents** of `website-svssg/` into
`svssg/site/bolte2025geometric/`, then build your website normally. The folder
must match `bolte2025geometric.org` so svssg places the page alongside its
assets. The Org page
is rendered by svssg's own template, so its header, navigation, theme control,
fonts and base styles come from the website. The export includes only the
paper-specific styles and interactive dependencies; it reuses the website's
fonts, stylesheets, MathJax configuration and MathJax loader. KaTeX and its
fonts are only included in the standalone export. The scoped stylesheet requires a browser with
CSS `@scope` support. Copy the entire directory, including `vendor/` and
`lean/`, to preserve the interactive features and source links.

The default `npm run export` remains the standalone version in `website/`;
the two exports have separate directories and archives.

Commit the maintenance project (including the pinned `source/paper/main.aux`,
source snapshots and lock files) if you want to retain it in Git. Upload artifacts,
temporary files and browser screenshots are ignored. Review the internal audit
materials before making the maintenance project public.
